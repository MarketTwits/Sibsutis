    Глава 6. Анализ и измерение производительности ВС

    1. Введение

    Производительность ВС [1] характеризует объем полезной работы, совершаемой ВС, по отношению ко времени или используемым ресурсам. Так как ВС имеет много компонент в своем составе, и сами компоненты имеют высокую сложность, на производительность ВС влияет большой набор факторов. Хорошая производительность ВС может складываться из малого времени ответа пользователю, высокой скорости обработки, малого объема задействованных ресурсов ВС и малой доли времени, когда ВС не функционирует нормально. Знание производительности ВС может потребоваться для различных целей. Во-первых, разработчики новых ВС, вносящих модификации в существующую архитектуру, должны иметь количественную информацию о том, в какой мере они улучшили параметры ВС. Во-вторых, при выборе подходящей ВС из существующих доступных, пользователь должен иметь возможность получить такую ВС, которая достаточна по своим возможностям для качественного решения его задач и оптимальна по важным для него параметрам (стоимость, надежность и т.д.). Наконец, пользователь уже имеющейся в наличии ВС, который составляет для нее свои программы или использует заемные, хочет оценить качество этих программ по части эффективности использования ими этой ВС.

     

    2. Метрики производительности ВС

    Под метрикой производительности ВС будем понимать систему параметров количественной оценки производительности ВС. Все метрики основываются на поведении системы во времени. Существует три основных класса метрик [2], которые наблюдаются пользователем снаружи системы: Метрики задержки или метрики времени ответа измеряются как задержка между запросом на выполнение некоторого действия и получением результата. Метрики скорости обработки измеряют количество работы, сделанное за единицу времени, или скорость поступления новых результатов. Метрики доступности измеряют долю времени, когда система доступна для нормальной работы. Четвертый класс метрик, метрики использования, наблюдаются внутри системы. Метрики использования важны для понимания и предсказания производительности.

    Задержка - время между началом и концом операции (или между запросом и ответом). Метрики задержки или времени ответа измеряются в единицах времени. Определение метрики задержки должно включать как момент начала, так и момент завершения события

    Примеры метрик задержки:

    1) время между вводом адреса в Web браузере и моментом, когда страница целиком отображена;

    2) время между нажатием клавиши установки соединения у сотового телефона и моментом, когда слышен сигнал вызова.

    Во многих случаях, задержка представляется распределением случайной величины, или времением, в которое она укладывается с указанной вероятностью. Например, у базовой станции сети сотовой связи может быть задержка в установке соединения, которая в 99.5% случаев не превышает одной секунды.

    Скорость обработки - работа, совершаемая за единицу времени (например, число операций в секунду). Часто термин "производительность" используют в узком смысле, для обозначения данного класса метрик. Для устройств передачи данных используют также термин "пропускная способность". Скорость обработки измеряется в единицах, обратных времени. Примеры метрик скорости обработки:

    1) объем данных, переданных по каналу связи, который измеряется в Мбит/сек;

    2) объем данных, записанных на ленту стримера, который измеряется в Гб/час;

    3) число транзакций в минуту;

    4) число доступов к памяти в секунду;

    5) число целочисленных операций, выполняемых ВС в секунду (MIPS);

    6) число операций над числами в формате с плавающей запятой, которые выполняются ВС в секунду (FLOPS).

    Производительность (в смысле скорость обработки) можно разделить на пиковую (максимальную, определяющую предельные возможности компонента ВС) и реально доступную. Отношение реально доступной к максимальной называют эффективностью. Для многих приложений производительность может быть приведена к другим метрикам, например, стоимость или потребление энергии. Зная число операций в секунду и потребляемую мощность у микропроцессора, можно вычислить, сколько энергии потребляется в расчете на одну операцию. Производительность может задаваться с указанием ограничений на максимальную задержку.

    Число целочисленных операций, выполняемых микропроцессором, (MIPS и FLOPS) может использоваться для указания как пиковой, так и реально доступной производительностей ВС. В первом случае оно определяется, исходя из числа микропроцессоров в ВС, их тактовой частоты и числа тактов, требуемых для выполнения операций. Сравнивать пиковую производительность для ВС с разной архитектурой затруднительно [3], так как они могут предоставлять разный набор операций. Соответственно, для решения одной и той же задачи потребуется выполнить разное число операций. Реально доступная производительность даже для одной и той же ВС зависит от того, какая программа исполняется. Если выбрать одну программу, то можно проводить сравнение реально доступной производительности самых разных ВС при ее исполнении. Программы, которые написаны для проведения таких сравнений, называют тестами на производительность (benchmark).

    Доступность - доля времени, когда ресурс доступен для использования (когда система функционирует в нормальном режиме). Например, доступность СУБД, которая не работает 1 час в сутки, - 0.96. При этом, доступность не является исчерпывающей характеристикой. При одинаковой доступности (0.96) эта СУБД может не работать 1 раз в сутки по 1 час или 1/24 секунды раз в секунду. Во втором случае СУБД совершенно бесполезна. Для количественного описания различия в этих двух ситуациях вводится метрика надежности - среднее время между сбоями [4](MTBF, Mean Time Between Failures). В первом случае оно равно одним суткам, во втором - одной секунде. С MTBF связана другая метрика - среднее время восстановления после сбоев (MTTR, Mean Time To Repair).

    Коэффициент использования - доля времени, когда компонент ВС активен (занят, используется). Ее значения лежат в диапазоне от 0 до 1 (по определению). Единица означает, что компонент используется полностью, т.е. его производительность равна максимальной производительности. Как правило, время ответа сильно увеличивается при коэффициенте использования близком к единице. Чтобы не допустить этого, иногда в системах вводят ограничение на максимальное значение коэффициента использования на уровне 0.7-0.8.

     

    3. Методики анализа производительности ВС

    Методики анализа производительности можно разделить на три класса:

    1) аналитическое моделирование;

    2) имитационное моделирование;

    3) измерение производительности.

    В двух первых классах строятся модели изучаемых ВС. В третьем происходит непосредственное наблюдение ВС. Ни один из классов не является лучшим решением для любого случая. Они имеют свои достоинства и недостатки. Выбор конкретного из них зависит от многих факторов, в частности, 1) имеется ли реально доступная ВС для анализа, или есть только ее модель, 2) какой требуется уровень точности, 3) какое время занимают измерение и моделирование и т.д. Как правило, при всестороннем анализе используются все классы. Сначала можно получить данные измерениями, далее их можно экстраполировать аналитическими методами для других ВС и приложений.

     

    4. Аналитическое моделирование

    Для аналитического моделирования требуется построение математической модели. Математическая модель является абстрактным представлением реальной исследуемой системы. Искусство анализа проивзодительности заключается в выборе хорошей модели, которая с одной стороны адекватно описывает существенные для рассмотрения параметры системы, а с другой стороны не перегружена несущественными параметрами.

    Аналитическое моделирование удобно для быстрой оценки производительности. Оно подходит для сравнения производительности нескольких разных систем. В анализе производительности ВС используется несколько методов аналитического моделирования.

    Вычисление граничных значений - набор простых вычислений для оценки максимальной производительности отдельной компоненты ВС. Например, Web сервер, подключенный по каналу с пропускной способностью 100Мбит/сек и рассылающий страницы размером 10КБ, может посылать не более 100*2^20/(8*10*1024)=1280 страниц в секунду. Хотя вычисления граничных значений просто вычисляются и являются понятными, их использование носит ограниченный характер. Они дают верхние, оптимистические оценки. Например, для рассмотренного Web сервера не были учтены следующие факторы, понижающие производительность:

    1) протоколы разных уровней посылают пакеты данных, в которых кроме самих передаваемых данных есть заголовки;

    2) кроме страниц по каналу передачи данных передаются запросы к Web серверу, а также, возможно, и другие данные.

    В вычислениях граничных значений нельзя вычислить задержки. В них также нельзя смоделировать взаимодействие между компонентами ВС. Основное использование данного метода - быстрое исключение заведомо нереализуемых вариантов построения систем.

    Модели анализа очередей [5, 6] основываются на теории массового обслуживания[7]. Они представляют ВС, как набор центров обработки запросов. Таким центром обработки может быть любой активный ресурс ВС (процессор, диск, сетевое соединение). С помощью моделей анализа очередей можно производить оценку задержек, максимальной производительности и коэффициента использования с приемлемой точностью (30% для задержек, 10% для максимальной производительности и коэффициента использования).

    Модели анализа очередей делятся на следующие группы:

    1) граничные асимптотические;

    2) открытые сетевые;

    3) закрытые сетевые.

    Граничные асимптотические - простейшие из моделей анализа очередей. Они служат для оценки граничных значений задержки и производительности одного центра обработки запросов. Граничные асимптотические модели обычно используются для изучения поведения ресурса, являющегося узким местом, при различных нагрузках на него. Ресурс, являющийся узким местом ВС, - тот ресурс, максимальная производительность которого наименьшая в системе, и который ограничивает общую производительность ВС. Расчеты в таких моделях - не трудоемкие, их можно провести вручную.

    В открытых сетевых моделях запросы однократно проходят через систему. Пример такой модели - сетевое устройство, обрабатывающее поток пакетов. Число обрабатываемых запросов в системе вычисляется по скорости пребывания запросов и характеристикам центров обработки. Если есть несколько типов запросов, то используются многоклассовые открытые сетевые модели. Для расчетов открытых сетевых моделей используют специализированное счетное программное обеспечение или электронные таблицы.

    В закрытых сетевых моделях число обрабатываемых запросов постоянно и известно, вычисляются производительность и задержка. Пример такой модели - ВС с разделением времени с фиксированным числом пользовательских терминалов. Как и открытые, закрытые сетевые модели могут быть одноклассовыми и многоклассовыми. Для подсчета производительности и задержки используется метод MVA (Mean Value Analysis). Есть две версии этого метода: для точных вычислений и для приблизительных вычислений. Вторая из них подходит для многоклассовых моделей с большим числом запросов.

    Сетевые модели имеют ряд недостатков. Ограничения, накладываемые ими, могут делать их сильно отличными от систем, которые они описывают. Кроме этого, сетевые модели плохо подходят для описания пассивных ресурсов ВС, например буферов.

    Цепи Маркова можно использовать для моделирования систем как конечного множества состояний с известной частотой перехода между состояниями. Они удобны для расчетов доступности ВС при заданных частоте отказа компонентов и частоте восстановления после сбоев. Также, они удобны для моделирования буферов и очередей с малым числом одинаковых элементов.

    5. Имитационное моделирование

    Имитационные модели реализуются посредством программы. Такое моделирование позволяет изучать систему на любом уровне детализации, учитывать все аспекты ее поведения, вычислять любые метрики производительности. Все параметры, заложенные в модель, представляются объектами данных (переменными) программы моделирования. Их совокупность определяет состояние моделируемой системы. В начальный момент времени они проинициализированы, и система находится в начальном состоянии. Далее, с течением времени, меняются значения некоторых, многих или всех переменных - система изменяет свое состояние. Моделирование можно проводить в непрерывном и дискретном времени. При этом имеется ввиду не реальное время, а время внутри модели (модельное время). При непрерывном времени изменение состояния системы происходит постоянно и непрерывно. В случае дискретного смена состояния происходит только в определенные моменты. Для моделирования ВС используют дискретное время. Модели с дискретным временем делятся на две группы:

    1) событийно-ориентированные;

    2) основанные на циклах.

    В событийно-ориентированных имитационных моделях активность системы представляется потоком событий. События могут случаться асинхронно. Интервалы времени между событиями - нерегулярные. Пример модели - файловый сервер, с такими событиями, как получение пакета данных из сети и завершение дисковой операции. Событийно-ориентированные модели годятся для самого широкого класса систем.

    В имитационных моделях, основанных на циклах, все изменения в состоянии системы синхронизированы с модельным временем. Пример такой модели - модель микропроцессора, в которой состояние меняется на каждом цикле. Модели, основанные на циклах, в некотором смысле можно рассматривать как частный случай событийно-ориентированных, если считать начало цикла событием.

    Имитационные модели можно реализовывать как с использованием языков высокого уровня общего назначения, так и пользоваться системами имитационного моделирования и языками моделирования, например, событийно-ориентированным языком моделирования Simula-67 [simula67]. Пример системы имитационного моделирования - система моделирования алгоритмов и структур с мелкозернистым параллелизмом WinALT[winalt, winalt2].

     

    6. Измерение производительности

    Измерение производительности осуществляется с помощью прогона тестовых программ. К настоящему моменту разработано большое число стандартных тестовых программ, измеряющих производительность всех компонентов ВС [benchlist, benchlist_paral_ru, benchlist_wisc]. Есть несколько фирм и некоммерческих организаций, которые разрабатывают наборы тестовых программ и собирают данные о производительности на широком спектре ВС [spec, tpc, eembc].

    Тест Dhrystone [dhrystone] написан в 1984 г. Он служит для измерения производительности ВС на целочисленных операциях и строковых операциях. Он включает в себя смесь команд, типичных для программ, написанных на языках высокого уровня. В частности, в нем есть адресная арифметика, вызов подпрограмм, операция присваивания. Результаты измеряются в собственных единицах - Dhrystone MIPS (DMIPS). С увеличением объемов кэш памяти и усложнением компиляторов, а также после появления тестов SPEC, Dhrystone перестал широко использоваться для различных классов ВС. Он по прежнему применяется для тестов во встраиваемых системах.

    Тест Whetstone[whetstone] написан в 1972 г. Предназначен для измерения производительности ВС на операциях над данными с плавающей запятой. Единица измерения - WIPS.

    Набор тестов CINT2006[cint2006] написан организацией Standard Performance Evaluation Corporation (SPEC). Он служит для измерения производительности ВС на операциях с целочисленными данными. Набор содержит 12 тестов, написанных на Си и Си++:

    1) интерпретатор Perl, исполняющий программу обработки почты (400.perlbench);

    2) архиватор, интенсивно работающий с оперативной памятью, но без обращений к диску (401.bzip2);

    3) компилятор Си, генерирующий код для микропроцессора Opteron (403.gcc);

    4) комбинаторная оптимизация - симплекс алгоритм для составления расписания транспорта (429.mcf);

    5) задачи искусственного интеллекта, игра Го (445.gobmk);

    6) анализ протеиновой последовательности с использованием скрытых Марковских цепей (456.hmmer);

    LINPACK[linpack] - библиотека для решения систем линейных уравнений методом Гаусса (а также других операций с матрицами, и, вообще, линейной алгебры), написанная в 70-х годах. Выполняет большое число операций над данными с плавающей запятой. Используется как тест на производительность суперкомпьютеров. В частности, список 500 самых быстрых ВС общего назначения в мире [top500] формируется по результатам этого теста. Единица измерения производительности по тесту - FLOPS. Самая быстрая ВС (общего назначения) на планете - IBM Blue Gene/L (360 TFLOPS). Самая быстрая ВС, создаваемая в настоящий момент (осень 2007 года), - Blue Gene/P с производительностью выше 1 PFLOPS (1 Peta FLOPS = 1000 Tera FPLOPS).

    Тест LFK (Livermore Loops) состоит из 24 циклов, представляющих собой характерные вычисления из различных областей прикладной физики. Вычисляет эффективность соответствующих фрагментов в MFLOPS с тремя наборами длин векторов.
